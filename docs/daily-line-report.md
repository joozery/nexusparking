# รายงาน LINE ประจำวัน

เมื่อเปิดระบบ Next.js/Electron แบบทำงานต่อเนื่องและเปิดการแจ้งเตือน LINE ในการตั้งค่า
ระบบจะสรุปวันก่อนหน้าที่เที่ยงคืนเวลาไทย ส่งไปยังผู้รับ LINE ที่ตั้งค่าไว้เดิม
เริ่มเก็บตารางส่งเมื่อเซิร์ฟเวอร์เปิดใช้ฟังก์ชันนี้ครั้งแรก ไม่ส่งข้อมูลเก่าก่อนวันเริ่มใช้
หากระบบหยุดทำงาน จะสร้างรายงานวันที่ค้างส่งทีละวันหลังเปิดระบบอีกครั้ง
เครื่องต้องเปิดและเชื่อมต่อฐานข้อมูล/อินเทอร์เน็ตจึงส่งตรงเวลาได้
ไม่รองรับการตั้งเวลาด้วย timer นี้บน serverless ที่พักโปรเซสเมื่อไม่มี request

## การนับ

- ช่วงรายวัน: 00:00 ของวันรายงาน ถึงก่อน 00:00 ของวันถัดไป เวลาไทย
- กะทั้งหมด: กะที่มีช่วงเวลาทำงานทับกับวันรายงาน แยกจำนวนเปิด ปิด และยังไม่ปิด
- เงินต้นกะรวม: เฉพาะกะที่เปิดวันนี้ เงินส่งคืนรวม: เฉพาะกะที่ปิดวันนี้
- รายได้: รายการรถออก completed/lost ตาม exitTime ของวันนี้ รวมค่าปรับแล้ว ไม่บวกเงินต้นกะ/ส่งคืน
- กะข้ามวัน: รายละเอียดการเงินของกะเป็นยอดรับเฉพาะวันรายงาน แสดงเงินต้นกะก่อนวันรายงานแยกชัดเจน
- ผู้เปิด/ผู้ปิด: ชื่อเจ้าของกะที่บันทึกไว้ ปัจจุบัน API อนุญาตให้ผู้ใช้ปิดกะของตัวเองเท่านั้น
- บัตรหาย: จำนวนรหัสบัตรไม่ซ้ำ พร้อมจำนวนรายการและยอดค่าปรับจริง
- รถเข้า: รวมคิว โดยใช้รหัสบัตรและเวลาเริ่มเป็นกุญแจป้องกันนับการย้ายคิวซ้ำ
- รถค้างและคิวรอ: คำนวณสถานะ ณ ขอบเขตเที่ยงคืน ไม่ใช่สถานะตอนส่งย้อนหลัง
- ข้อมูลถูกลบหรือเวลาเข้า/ออกถูกแก้ย้อนหลังจะมีผลต่อรายงานที่ยังไม่ได้สร้าง

## การส่งและตรวจสอบ

ไปที่ ตั้งค่า → LINE แจ้งเตือน → รายงานประจำวันตอนเที่ยงคืน เลือกวันที่ก่อนวันนี้
กด “ดูตัวอย่างรายงาน” เพื่อดูข้อมูลจริงโดยไม่ส่งข้อความ จากนั้นกด “ส่งรายงานทดสอบเข้า LINE”
เพื่อส่งไปยังผู้รับที่บันทึกไว้ ข้อความมีคำว่า “ทดสอบ” และไม่แก้สถานะงานอัตโนมัติ
ทดสอบตัวคำนวณโดยไม่แตะฐานข้อมูลหรือส่งข้อความด้วย `node scripts/test-daily-report.cjs`

`dailylinecursors` เก็บวันที่ต้องส่งถัดไป; `dailylinejobs` เก็บข้อความแต่ละส่วนและสถานะส่ง
ข้อความยาวแบ่งหลายส่วนตามลำดับ แต่ละผู้รับมีสถานะของตนเองและ retry key ถาวร
ระบบตรวจผลตอบกลับจริง ไม่ถือว่า HTTP error เป็นส่งสำเร็จ
การส่งล้มเหลวชั่วคราวจะลองใหม่หลัง 5 นาที; ไม่ลองซ้ำหลัง 23 ชั่วโมงจากการส่งส่วนนั้นครั้งแรก
HTTP 4xx ที่ไม่ใช่ rate limit หรือหมดเวลาลองซ้ำจะเป็น `needs_review` ให้ตรวจในฐานข้อมูล/บันทึกเซิร์ฟเวอร์
อย่าลบงานเพื่อส่งซ้ำโดยไม่ตรวจข้อความปลายทางก่อน

อ้างอิง retry key: https://developers.line.biz/en/docs/messaging-api/retrying-api-request/
